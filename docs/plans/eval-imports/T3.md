## Findings, local analysis (18 traces, 3 cases x 2 arms x 3 runs, one suite, claude 2.1.280, model claude-sonnet-5)
Only one suite and one Claude Code version observed: everything below is "true for this sample", not a guarantee.

### results.json
- Top-level keys: `aggregates, cases, claudeVersion, costUsd, durationSeconds, partial, schemaVersion, startedAt, suite`. `schemaVersion: 1`, `partial: false`.
- Each case: `name, source, runsPerCase, maxTurns, promptMarkdown, arms{with[],without[]}, graders[], aggregates, dir, timeoutSeconds`. All 3 cases have 3+3 runs, 0 runs with `error`.
- `partial` exists: a partial run (interrupted eval) must be handled. Policy proposal: import allowed, flagged "partial" in manifest/UI; missing traces for unfinished runs tolerated ONLY when `partial: true`. (Needs user decision, see below.)
- `aggregate-result.json` is byte-identical to `results.json` (cmp). `tracePath` values are CI temp paths, unusable.

### Trace lines (all 18 files)
| type/subtype | count | has timestamp | adapter action |
|---|---|---|---|
| `system/init` | 18 | no | keep as session metadata (model, cwd, tools, version); do not render as a message |
| `system/thinking_tokens` | 1291 | no | drop (estimates only) |
| `system/permission_denied` | 8 | no | NEW subtype, not seen in my earlier pass. Has `tool_name`, `tool_use_id`, `message`. Candidate: surface as a note attached to that tool call. Decide in S4 |
| `assistant` | 744 | yes | one line per content block; same `message.id` repeated (1 to 6 lines per id). `stop_reason` is null on these lines |
| `user` | 518 | yes | ALL are `tool_result` arrays. `tool_use_result` is an object (500) or a string (18, the string cases are `is_error: true`) |
| `result/success` | 18 | no | final line: `num_turns`, `duration_ms`, `total_cost_usd`, `stop_reason: end_turn`, `terminal_reason: completed`, `usage`, `result` (string) |

- Content block types: `thinking` 145, `text` 81, `tool_use` 518. No `Task` calls, no non-null `parent_tool_use_id`.
- No `parentUuid`, no `isMeta`, no per-line `cwd`. Each line has `uuid` and `session_id`.
- Real Claude Code session files (`~/.claude/projects/...`, checked structure only: types and `message.id`, no content) ALSO split an assistant message across lines with the same `message.id`. So per-block splitting is not new to the existing parser; confirm in S4 how `ChunkBuilder`/`SessionParser` merges them.
- `tool_use_result` object shapes seen: Write/Edit (`filePath, originalFile, structuredPatch...`), Read (`file, type`), Bash (`stdout, stderr, interrupted...`), Glob/Grep (`filenames, numFiles...`). Same family as real sessions (not compared field by field; unverified).

### Adapter contract (proposal)
1. Drop `system/thinking_tokens`; keep `init` as metadata; map `permission_denied` to an annotation (decide in S4).
2. Prepend a synthetic real-user message (`isMeta: false`, string content = case `promptMarkdown`), timestamp = first assistant timestamp minus 1 ms (or `startedAt` of the run).
3. Mark `tool_result` user lines `isMeta: true` (matches the "internal message" definition in CLAUDE.md).
4. Synthesize `parentUuid` by chain order (previous line's `uuid`), since trace has none.
5. Use `result` line for run totals shown in the header; do not re-derive cost from usage.
6. Reject the trace if `system/init` is missing, or `claude_code_version`/`schemaVersion` is outside the verified set; show a clear message with the version found.

## Findings, docs lookup (approved WebFetch of https://code.claude.com/docs/en/plugin-evals; page content saved locally and grepped, 60 KB, treated as reference data; no embedded instructions acted on)

### Documented
- `aggregate-result.json` and `--json` output are the same versioned document, `schemaVersion: 1`, camelCase. **"new fields are added without renaming existing ones, so write your script to ignore fields it doesn't recognize."** => Policy: accept `schemaVersion === 1`, ignore unknown fields, reject any other schemaVersion with a clear message. No need to pin `claudeVersion`.
- Default output dir `<eval dir>/results/<timestamp>/` holds `aggregate-result.json` and `report.html`. Baseline runs are `cases[].arms.without`.
- `partial: true` + `partialReason` in {`cost_ceiling`, `interrupted`, `auth_failed`}; exit code 2 (ceiling/credential) or 130 (interrupted), partial results still written. Docs: leave partial results out of trend charts.
- Per-run fields beyond what we saw: `aborted` (mock stopped the run: `server`, `tool`, `reason`; run scores 0, `error` stays null), `skippedPaidGraders` (judge graders skipped by cost ceiling; score not comparable), `error` (non-null does not imply score 0).
- Rate-limit/plan-limit runs are NOT marked partial; they show in `cases[].arms.with[].error`. Viewer should surface `error` prominently.
- `delta` omitted when a case ran one arm (e.g. `context.history_file` with a path target) => matrix must handle cases with only a `with` arm.
- Graders see the session as "JSON, one message per line" (trace); this is the only mention of the trace format. **The trace file format and any subagent/`parent_tool_use_id` handling are NOT documented on this page.**

### NOT documented: the `traces/` layout is a convention of the user's CI, not Claude Code
- `.github/workflows/mf-sast-evals.yml` runs `evals/run.sh ... --keep-temp --json results.json --output-dir ...`, then `python3 evals/summarize.py results.json --traces-out <dir>/traces`.
- `evals/summarize.py` `copy_traces()` copies each run's `tracePath` to `<out_dir>/<case>/<arm>-<n>.jsonl` (verified by grep: comment at line 194-195, `run.get("tracePath")` at 199). Official CLI only keeps the trace if `--keep-temp` is passed.
- Consequences:
  1. The "eval-run bundle" is a claude-devtools format defined by us; it happens to equal the mf-sast artifact. Must be documented as such (README, error messages).
  2. Other suites in the same repo (e.g. `ai-sdlc-evals.yml`) may or may not use the same script; unverified.
  3. A raw `results/<timestamp>/` directory from a local run has NO `traces/` and `tracePath` points at a temp dir. It is not importable; error message must say how to produce a bundle (`--keep-temp` + copy traces to `traces/<case>/<arm>-<n>.jsonl`).
  4. Optionally later: ship a small script/snippet users can run to build a bundle from a local `--keep-temp` run.

### Version policy (final proposal)
- results.json: `schemaVersion` must equal 1; unknown fields ignored; required fields validated (`cases[].name`, `arms.with|without[]`, `runsPerCase`, `graders`) with explicit errors.
- Trace: no documented schema => tolerant reader: require at least one `assistant` line and ignore unknown line types/subtypes (the sample already had 5 type/subtype combos). Do not gate on `claude_code_version`; record it in the manifest and show it. **Replaces adapter-contract item 6 from the local analysis** (that gate would reject traces needlessly).
- Warn (banner) rather than reject when the trace has no `system/init` or no `result` line (killed run).
