# T4: import:<id> URL / deep-link / validation scheme
Type: grilling (HITL) | Status: done | Blocked by: T2

## Question
How is an import addressed in tabs, routes and IPC/HTTP, and what exactly does `validateProjectId` accept?

## Options to settle
- Deep link shape: `/import:<id>/<sessionId>` vs `/imports/<id>/<sessionId>`.
- Eval-run tab identity and restore after restart.
- ID format (UUID v4?) and strict regex; reject everything else.
- How a trace is named as a session id (e.g. `<case>~<arm>-<n>` mapped server-side to a file, never used as a path).
- Where `isImport()` lives so every service checks one function.

## Output
Decision recorded here and in MAP.md "Decisions so far".

## Decisions (user accepted)
- T4.1: trace eval id = opaque server-generated (`t001`, `t002`...), mapping `id -> relative path + case/arm/n` stored in `manifest.json`. Case names are display labels only, never part of a path. Reason: case names come from the sender.
- T4.2:
  - Import id = lowercase UUID v4 from `crypto.randomUUID()`, server-generated.
  - `projectId` = `import:<uuid>`, exact anchored regex, single `isImportProjectId()`; no `~`.
  - Session-type import: sessionId = real session UUID. Eval-run: `t\d{3,}`.
  - URLs (urlRouting regex unchanged; `:` round-trips via `%3A`, checked in `urlRouting.ts`): `/import:<uuid>` = overview (matrix for eval-run, the single session for session-type); `/import:<uuid>/<sessionId>` = session/trace.
  - New tab type `eval-run` (carries `importId`); traces use normal `session` tabs with `projectId = import:<uuid>`.
  - `App.tsx:28` deep-link branch for `import:*` opens the tab directly, no project selection; deleted import shows "import no longer exists".
