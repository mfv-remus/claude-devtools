# T5: Import dialog UX
Type: grilling (HITL) | Status: done | Blocked by: -

## Question
What does the import flow look like from click to a visible import?

## Options to settle
- Fields: type (required), name (required), zip file; default name suggestion.
- Upload progress and cancel; size limit shown up front.
- Validation errors: list all problems (missing trace, bad version) vs first only.
- Preview-before-save step or save directly (summary shown after).
- Behaviour when `IMPORTS_READONLY=true` (hide button vs disabled with reason).
- Duplicate-name warning; rename/delete/reload menu; delete confirmation.

## Output
Decision recorded here and in MAP.md. Use design-system skill for styling afterwards.

## Decisions (user accepted)
- T5.1: single-step import. Dialog: type (required), name (required, default = zip filename without `.zip`, max 80 chars, editable), `.zip` file. `POST /api/imports` uploads, server extracts to temp, validates, saves or rejects. On failure the dialog stays open and lists ALL validation errors. On success it closes and opens the new import. No preview step, no server-held temp state, no TTL. Summary shown after import (list + overview). Upload progress by bytes with Cancel; 200 MB limit shown and pre-checked on the client (server is the source of truth). Duplicate names: warn, allow.
- T5.2:
  - Menu per import: Rename (in place, atomic manifest rewrite), Delete (existing `ConfirmDialog`, names the import, "cannot be undone"), Copy ID. **No Reload** (imports are immutable; re-import creates a new one). Supersedes Q8's menu.
  - Open tabs of a deleted import show "import no longer exists".
  - `GET /api/imports/capabilities` -> `{ enabled, readonly }`. `IMPORTS_ROOT` unset: hide Imports entirely (also Electron v1). `IMPORTS_READONLY=true`: list + view stay, Import/Rename/Delete hidden with a small "read-only" note. Server enforces (403); UI is convenience only.
  - Invalid entries (missing/corrupt manifest): row "invalid" with the directory name, only action Delete.
- Styling later via the design-system skill (theme variables only).
