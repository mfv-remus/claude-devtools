## Findings, network part (approved fetches; summaries produced by the fetch tool, not verbatim; GitHub READMEs only, no npm pages)
Sources: github.com/fastify/fastify-multipart, github.com/thejoshwolfe/yauzl, github.com/101arrowz/fflate.

### @fastify/multipart
- MIT. Limits: `fileSize` (defaults to fastify `bodyLimit`, 1 MiB, so MUST be raised explicitly), `files`, `fields`, `parts`, `fieldSize`, etc.
- README warns `bodyLimit` is not an aggregate cap across the multipart payload: set `files: 1`, `fields`, `parts` and `fileSize` explicitly.
- Stream to disk: `await pipeline(request.file().file, fs.createWriteStream(tmp))` (we choose our own temp path, never `data.filename`). Unconsumed stream hangs the promise; check `file.truncated` after pipeline to detect a size-limit hit.
- NOT verified: which fastify major the current release supports (page silent), latest version/date. Check npm `peerDependencies` before pinning (needs another approved lookup, or `pnpm view` which is also network).

### Zip libraries
| | yauzl 3.x | fflate 0.8.x |
|---|---|---|
| License | MIT | MIT |
| Entry inspection before extract | yes: `fileName`, `uncompressedSize`, `compressedSize`, `externalFileAttributes`, `isEncrypted()`, `entryCount` | `Unzip` stream: `file.name`, `size`, `originalSize` (sometimes undefined); `file.start()` to extract |
| Zip-slip | built in: `validateFileName` rejects leading `/`, drive letters, `..`, backslashes (only when `decodeStrings: true`, the default) | none documented |
| Symlink detection | raw `externalFileAttributes`, no helper (we decode Unix mode bits ourselves) | not documented |
| Size lies | `validateEntrySizes` (default true) errors mid-stream when actual size differs | not documented |
| Input | random access on a file path (fits "upload to temp file, then open") | streaming or in-memory (`unzipSync` loads everything) |
| Limits | no streaming API; only methods 0 and 8; no encryption; CRC32 not verified; no multi-disk | ~4 GB; 30 open issues / 18 PRs; maintenance unclear from page |

### Recommendation
**yauzl 3.x + @fastify/multipart**, both pinned exact versions.
- yauzl matches our flow (upload to temp file, validate entry list, then extract): random access, metadata before any write, built-in name validation, size validation.
- Our checks on top (yauzl explicitly leaves bomb heuristics to the caller): reject if `entryCount` > cap; sum `uncompressedSize` of all entries > 1 GB before extracting anything; reject encrypted entries; reject entries whose Unix mode (`externalFileAttributes >>> 16`) is a symlink (verify the bit test with a generated zip in a unit test); per-entry byte counter while streaming; reject names not on our whitelist (`results.json`, `traces/<case>/<arm>-<n>.jsonl`, or the session layout); write to our own path built from validated parts, `flag: 'wx'`, then atomic rename of the temp dir.
- Rejected: fflate (no documented name validation or symlink info, in-memory sync API tempting for big files, unclear maintenance).
