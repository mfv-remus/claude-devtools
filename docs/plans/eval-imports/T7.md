### Caveats found while checking
1. `${UID}` / `${GID}` are shell variables, not exported env vars, so Compose will NOT see them by default; `${UID:-1000}` silently falls back to 1000. On macOS (uid 501) with Docker Desktop, bind mounts are mapped by the VM so this mostly works; on Linux a host uid other than 1000 breaks write access. Fix: put `UID=...`/`GID=...` in a `.env` file next to the compose file, or `export UID GID` before `docker compose up`. (No `.env` exists today.)
2. `~/.claude-devtools/imports` does not exist on this machine yet. If Docker creates it, it will be root-owned on Linux.
3. Pre-existing, unrelated: config is written to `CLAUDE_ROOT/claude-devtools-config.json` (`standalone.ts:100`) but `~/.claude` is mounted `:ro`, so config writes cannot succeed in this compose. Imports do not use that file. Left as is.
4. `user:` forces non-root; reading `~/.claude` (`:ro`) then depends on that uid being able to read the host files. Same uid as the host user is the normal case.
5. A named volume would avoid host-permission problems, but the user chose a host bind mount (`$HOME/.claude-devtools/imports`) for easy backup/inspection.
